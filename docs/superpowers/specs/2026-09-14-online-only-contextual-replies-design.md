# LexPilot 全应用强制联网与个案化回复设计

日期：2026-09-14

## 目标

LexPilot 的劳动争议专线与综合咨询统一使用外部大模型生成面向用户的最终回复。规则引擎继续负责事实、证据、法源、程序状态、安全信号和行动选择，但不再把固定开场、固定衔接词或通用追问直接展示给用户。

成功标准：

- 每轮回复先回应用户本轮表达，再结合本案已记录事实继续分析或追问。
- 用户可见回复不再出现无事实依据的固定标题和通用串场话术。
- 紧急安全提示仅在规则识别到相应信号时出现，并由模型结合本案自然表达。
- 劳动争议和综合咨询使用同一联网门槛及错误语义。
- 未配置密钥、鉴权失败、超时、网络异常或模型输出校验失败时，不生成离线咨询回复。
- 联网失败不会丢失已成功保存的对话、上传材料或此前案件状态。

## 不在本次范围内

- 不让大模型替代确定性的事实槽位、证据状态、法律检索或规则路由。
- 不取消证据与法源校验，不放宽禁止保证结果、编造金额和虚构引用的限制。
- 不把测试套件改为调用真实外部服务；测试使用可注入的模拟模型。
- 不改变附件上传、报告格式或现有案件数据结构；联网状态只作为请求期结果和错误响应存在，不写入案件模型。

## 方案选择

采用“确定性案件引擎 + 统一联网回复生成器”。

只删除文案池不能消除模板感；完全由模型接管流程又会削弱事实和法源约束。统一生成器位于案件处理完成与 UI/API 返回之间，以结构化的本轮回复任务作为唯一输入，既保留现有审计能力，也允许模型按案件上下文自然表达。

## 架构

新增统一在线回复模块，职责如下：

1. 检查外部模型提供方是否可用；缺少有效配置时立即失败。
2. 从案件状态和本轮处理结果构造结构化回复任务。
3. 请求模型生成单条自然回复。
4. 校验回复是否满足本轮目标、问题数量、案件锚点、安全要求和引用约束。
5. 首次校验失败时，把明确错误反馈给同一外部模型纠正一次。
6. 请求或纠正仍失败时抛出统一的联网模型异常，不返回模板文本。

处理链路：

```text
用户消息
  -> 规则提取、领域路由、证据及法源处理
  -> 结构化回复任务
  -> 外部模型生成
  -> 确定性输出校验
  -> 合格回复
       或
     一次联网纠正 -> 合格回复 / 联网模型异常
```

## 回复任务

回复任务至少包含：

- 用户本轮原话（发送前执行现有脱敏）。
- 首次叙述和最近案件上下文。
- 咨询者身份及对方身份；不明确时标记为未知。
- 已记录事实及其来源状态。
- 已有、缺失、冲突和无法取得的材料。
- 用户目标、处理限制和已完成程序。
- 规则层选择的本轮动作及原因。
- 本轮必须传达的安全事项。
- 需要回答的直接问题、需要追问的事实 ID 及追问目的。
- 已核对法源和允许引用的来源 ID。
- 已生成行动方案中与本轮最相关的部分。
- 回复模式：接谈、回答问题、单步建议、方案摘要或详细方案。

规则层可以保留内部问题模板作为槽位说明和模型约束，但这些文本不能直接成为最终回复。

## 模型输出约束

模型返回结构化对象，至少包含 `reply` 和 `asked_fact_ids`。最终展示只使用通过校验的 `reply`。

提示词要求：

- 像耐心、务实的法律顾问一样直接回应，不自称律师或律所。
- 不使用“我先和你一起梳理”“现在最希望得到什么结果”等固定开场。
- 不复述用户已经给出的事实，不重复已经问过、拒答或不知道的问题。
- 需要追问时，解释该问题如何影响判断，并且默认每轮只问一个问题。
- 只有存在安全或期限信号时才表达紧急建议；措辞应指向具体风险。
- 不编造事实、机构地址、胜率、结果保证、法定截止日或未经提供的法条。
- 用户要求方案时，建议必须使用本案金额、日期、材料、身份或争议点等个案锚点。

## 校验

校验器执行可解释的确定性检查：

- 回复非空且长度在允许范围内。
- 追问数量不超过用户允许的数量。
- `asked_fact_ids` 只能来自本轮允许追问的事实 ID。
- 不追问已经回答、拒答或确认不知道的事项。
- 有强制安全事项时，回复必须覆盖其核心动作；没有紧急信号时禁止出现通用紧急标题。
- 方案类回复至少包含当前案件的个案锚点。
- 具体法条引用只能来自本轮允许来源。
- 禁止胜率、保证性措辞和危险取证建议。

校验失败时进行一次联网纠正。纠正失败即返回服务不可用错误，不拼接任何离线替代文本。

## 综合咨询改造

- `process_consultation` 保留路由、事实吸收、证据刷新、检索、方案构建和待追问事实选择。
- `_case_opening`、`_follow_up_analysis`、`QUESTIONS` 和 `WordingComposer` 不再直接提供用户可见回复。
- 现有语义分析仍可生成结构化分析和行动步骤，但最终由统一生成器组织为一条连贯回复。
- “不知道”“没有更多材料”等特殊输入仍由规则层更新状态，然后交由模型结合上下文回应。

## 劳动争议专线改造

- ASK_FACT、REQUEST_EVIDENCE、阶段方案、单步回答、报告完成和人工复核等路径均改为先形成结构化回复任务。
- 原有事实提取、信息增益排序、证据图、金额计算和生成前核验保持不变。
- 固定的劳动追问、文案池、阶段方案前后缀和紧急事项标题不再直接展示。
- 劳动报告的模型生成失败不再回落为用户可见的确定性报告文案；内部结构可保留用于重试和审计。

## 错误处理

定义统一异常类型，至少区分：

- `not_configured`：没有有效密钥或联网模式被关闭。
- `authentication_failed`：外部服务返回 401/403。
- `temporarily_unavailable`：超时、网络异常、限流或上游 5xx。
- `invalid_response`：两次模型输出均未通过结构或安全校验。

Streamlit 显示简洁且可操作的提示，例如“联网法律分析暂时不可用，本轮没有生成离线回复；请检查密钥或稍后重试”。技术详情保留在折叠区域，但不得包含密钥、请求正文或模型原始敏感响应。

FastAPI 对这些错误统一返回 HTTP 503 和稳定的错误代码。鉴权失败对客户端仍使用 503，避免把上游认证细节误解释为本地用户权限错误。

## 状态一致性

联网调用前先在临时案件副本上完成本轮规则处理；只有模型回复通过校验后才提交新状态。失败时保留调用前状态和用户已上传的原始文件记录，避免出现“页面报错但案件已悄悄推进”。

对上传请求，文件安全接收和落盘可以先完成；模型失败时文件应明确显示已接收但本轮分析未完成，重试时不得重复落盘。

## 测试策略

严格测试先行：

1. 先写失败测试，证明无提供方、鉴权失败和超时时不会生成离线回复。
2. 验证综合咨询与劳动专线的所有用户可见回复都调用统一在线生成器。
3. 验证固定标题和典型模板衔接不再直接出现在输出中。
4. 验证生成器收到当前案件的事实、材料、目标、程序进展和用户限制。
5. 验证安全信号存在时必须覆盖安全动作，不存在时不输出通用紧急提示。
6. 验证追问只针对未回答事实，并默认每轮最多一个。
7. 验证首次不合格时只纠正一次，第二次失败返回统一错误。
8. 验证 Streamlit 保留旧状态并显示可操作错误。
9. 验证 FastAPI 返回 503 和稳定错误代码。
10. 运行现有核心回归测试，更新原先明确断言离线模板的旧测试，使其验证新的在线行为和安全不变量。

测试中的模拟提供方属于可重复的依赖替身，不构成生产离线回复能力。生产路径始终要求真实外部模型。

## 配置与运行

生产默认要求：

```text
LEXPILOT_ENABLE_SEMANTIC_AI=true
DASHSCOPE_API_KEY=<有效密钥>
QWEN_MODEL=qwen3.8-flash
```

保留模型地址、超时和模型名称配置。删除或停用“缺少密钥时继续规则回复”的用户可见行为。健康检查报告联网配置状态，但不在每次 `/health` 调用时消耗模型额度；真实可用性以最近一次模型调用结果和单独的诊断请求为准。

## 安全与隐私

- 沿用现有脱敏逻辑，原始附件正文不自动发送给外部模型。
- 回复任务只携带完成本轮咨询所需的最少信息。
- 日志不得记录密钥、Authorization 头、完整模型请求或未经脱敏的案件文本。
- 外部模型只负责表达和受约束分析；规则层仍是安全与法源边界的最终控制者。
